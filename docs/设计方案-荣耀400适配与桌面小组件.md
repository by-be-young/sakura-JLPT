# 樱花日语 × 荣耀400：适配与桌面单词小组件设计方案

> 状态：设计方案（未实施，不改动任何代码）
> 目标机型：荣耀 400（MagicOS 9，Android 15 底层）
> 目标能力：① 软件在荣耀 400 上流畅可用；② 桌面小组件常驻提醒学习；③ 组件随机展示一个「待复习（优先）或未学习」的单词；④ 组件功能**仅荣耀手机可见可用**；⑤ 组件能力**按需下载**（不进基础安装包）。

---

## 1. 现状盘点（依据现有代码）

| 事项 | 现状 | 结论 |
| --- | --- | --- |
| 移动端工程 | `android/` 为 Capacitor 8 Android 工程，包名 `com.sakura.japanese`，已可产出 APK | 荣耀 400 可直接安装，无需重构 |
| 背词状态 | `sakura_word_state_v1`：`learned{learnedAt,wrongCount,reviewCount,lastReviewAt,types}`、`familiar`、`notes`、`settings` | 已有完整的"已学/生疏"判定 |
| 复习判定 | `isDueForReview()`：`wrongCount ≥ 2` 或 `距上次复习 ≥ 2 天`；`dueWords()` 返回全部到期词；`unseenCount()` 返回未学数 | **直接复用，不用新造轮子** |
| 单词数据 | `src/data/words.js`：`{ id, level, kanji, kana, pos, meaning, examples }` | 组件快照直接取自该库 |
| 复习/学习页 | 路由 `/words/review`（复习）、`/words/learn`（新学） | 组件点击跳转目标 |
| 云同步 | Supabase `user_profiles.word_state`，登录后自动拉取合并（`useSync`） | 组件数据"应用打开即最新" |
| 离线 | 无网络时纯本地可用 | 组件快照本地化，离线也能显示 |

**核心结论**：小组件所需的状态判定（哪些词待复习、哪些未学）在 `wordStore` 中已经存在，方案只在两端新增能力——前端生成"组件快照"、Android 原生渲染该快照，不改变现有学习逻辑。

## 2. 荣耀 400 适配方案

### 2.1 安装与分发
- 现状 debug APK 可直接侧载到荣耀 400：`设置 → 应用 → 允许安装未知应用`。
- 正式使用建议：按 README §五 生成 `sakura.keystore` 签名后出 release 包，签名一致才能覆盖安装。
- 安装后需手动开启：**通知权限**（首次使用组件提醒时请求）、**后台运行**（见 2.3）。

### 2.2 UI 适配清单（荣耀 400：6.7 英寸、约 20:9、打孔屏、120Hz）
| 项目 | 做法 |
| --- | --- |
| 安全区/打孔屏 | 页面顶部避开摄像头打孔：CSS `env(safe-area-inset-*)` 补齐顶部/底部 inset；状态栏用沉浸式 + 半透明背景 |
| 深色模式 | 现有 `sakura_theme_v1 = light/dark/system` 已支持，真机回归深色下的对比度 |
| 字体缩放 | 系统字体放大 1.3 倍时页面不破版（现有移动端 CSS 已验证，真机复核） |
| 触控目标 | 单词作答选项、底部 Tab 热区 ≥ 48dp，防误触 |
| 横竖屏 | 沿用现有竖屏优先策略，横屏仅做兜底可用 |

### 2.3 MagicOS 系统级适配（关键）
荣耀手机管家的**后台管理/耗电优化**会延迟甚至阻止后台定时任务，直接影响小组件刷新与提醒可靠性。对策：

1. 应用内引导页（设置页新增入口）指导用户：`手机管家 → 应用启动管理 → 樱花日语 → 手动管理（允许自启动/关联启动/后台活动）`，并把应用设为"电池优化白名单"。
2. 组件刷新**不依赖**后台定时器存活：快照数据在应用每次打开/学习时立即写入，组件读取的是磁盘快照，应用不活跃时仍能显示最近一次内容（只是不更新）。

## 3. 桌面小组件总体设计

### 3.1 技术选型：原生 AppWidget（唯一可行路线）
| 候选 | 可行性 | 结论 |
| --- | --- | --- |
| **Android 原生 AppWidget**（在现有 `android/` 工程内加 Provider + RemoteViews 布局） | ✅ 标准能力，荣耀桌面/华为桌面均支持 | **采用** |
| PWA 小组件 | ❌ Android 系统未向 PWA 开放主屏小组件 API，荣耀桌面同样不支持 | 排除 |
| 常驻通知伪装"组件" | ⚠️ 不是桌面组件，用户不可自定义位置 | 仅作提醒补充 |

实现形态：Android 原生层新增一个 AppWidgetProvider；前端（Vue）通过一个极小的 Capacitor 本地插件把单词快照写入应用私有存储；组件进程只做"读快照 → 渲染 → 点按跳转"，不碰 WebView、不联网、不依赖登录态。

### 3.2 架构与数据流

```
┌─ 应用内（Vue 层，复用现有 wordStore）────────────────┐
│  学习/复习 → wordState 变化 → 生成快照(候选池)        │
│  dueWords() 优先 → 无到期词则取未学词 → 最多 30 条     │
│        │  via 本地 Capacitor 插件                     │
│        ▼                                              │
│  应用私有存储 widget_snapshot.json（含时间戳）          │
└───────────────────────────────────────────────────────┘
                         │ 独立进程读取
                         ▼
┌─ 桌面组件（Android 原生）────────────────────────────┐
│  RemoteViews 渲染：随机取 1 条 → 单词/假名/释义/徽标   │
│  刷新时机：系统周期刷新 + WorkManager + 点按"换一换"   │
│  点按整卡 → Deep Link 跳转 /words/review              │
└───────────────────────────────────────────────────────┘
```

- 未登录/纯本地模式：快照照常生成（localStorage 即权威数据）。
- 登录后：`useSync` 合并云端数据 → 重建快照 → 组件数据自动与云端一致。

### 3.3 组件形态（两种尺寸，荣耀桌面网格约 4 列）

**2×2 小卡（推荐默认）**
```
┌──────────────────┐
│ 🌸 樱花日语  待复习 3 │   ← 品牌行 + 状态徽标(待复习N / 新词)
│                    │
│    勉強           │   ← 单词(kanji，纯假名时用kana)
│    べんきょう      │   ← 假名
│    学习，用功       │   ← 中文释义(截断2行)
│  [去复习] 今日 5/20 │   ← 行动按钮 + 今日进度
└──────────────────┘
```

**2×3 中卡（信息更全）**：在小卡基础上增加"本词状态行"（如：错 3 次 / 已复习 2 次 / 距离上次复习 5 天）与"今日待复习总数"。

样式基调沿用应用现有樱花主题（粉白渐变 + 大圆角卡片），深浅色各出一套背景图（RemoteViews 不支持 CSS，用 XML 背景 drawable）。

### 3.4 单词选择与随机逻辑（复用现有判定）

```
候选池生成（应用内，状态变化时执行）：
  1. due = dueWords(当前等级词库)          // wrongCount≥2 或 超2天未复习
  2. 若 due 非空 → 池 = due（去 familiar）  // 待复习优先
  3. 否则 → 池 = 未学词（!isLearned，去 familiar）
  4. 截取前 30 条写入快照（每条含 review|new 标记）
随机展示（组件侧，每次刷新重抽）：
  池内 uniform 随机取 1 条；"换一换"按钮触发重新抽取
```

- 随机在组件侧完成 → 每次刷新/点按都可能换词，无需应用参与。
- 快照带 `generatedAt`：超过 24h 未更新时，组件文案切换为"打开应用同步最新单词"，避免展示过期数据（词库样例数据 7200 词，可接受）。

### 3.5 快照数据结构（`widget_snapshot.json`）

```json
{
  "v": 1,
  "generatedAt": 1762400000000,
  "level": "N5",
  "dueCount": 3,
  "newCount": 241,
  "today": { "done": 5, "goal": 20 },
  "pool": [
    { "id": 1024, "kanji": "勉強", "kana": "べんきょう", "meaning": "学习，用功", "level": "N5", "tag": "review" },
    { "id": 103, "kanji": "", "kana": "ありがとう", "meaning": "谢谢", "level": "N5", "tag": "new" }
  ]
}
```

`pool` 上限 30 条 × 约 120 字节 ≈ 4KB，写入私有目录，无隐私风险（不含账号信息）。

### 3.6 刷新机制（三级，互相兜底）

| 级别 | 触发 | 说明 |
| --- | --- | --- |
| 即时 | 应用内学习/复习/登录合并后 | 快照重建，组件下次可见刷新即更新 |
| 周期 | WorkManager（约每 2 小时，非精确） | 应用未被打开时的后台更新；受 MagicOS 后台策略影响，允许延迟 |
| 兜底 | AppWidget `updatePeriodMillis`（系统最小值 30 分钟） | 系统级最小保障 |
| 手动 | 组件上"换一换"按钮 | PendingIntent 广播 → onReceive 里重选随机词并刷新视图 |

### 3.7 点击行为（Deep Link 跳转）
- 整卡点击：自定义 URL Scheme（如 `sakura://words/review`）或 Intent 带 extra → `MainActivity` 启动并带参数 → Vue 路由跳转 `/words/review`（池中有待复习词时）或 `/words/learn`（纯新词时）。
- 荣耀桌面/系统均支持组件 PendingIntent 启动 Activity，无需额外授权。

### 3.8 提醒机制
1. **常驻提醒（组件本体）**：待复习数、今日进度始终可见；有到期词时徽标高亮（"待复习 N"）。
2. **可选每日通知（P0 之后）**：WorkManager 每日在用户设定时间（默认 19:00）发一条通知，正文随机展示一个词 + "去复习"动作。需首次请求 `POST_NOTIFICATIONS` 权限（Android 13+）。设置页提供开关与时间选择。
3. 不依赖通知权限时组件仍完整可用（权限只影响通知）。

## 4. 荣耀专属与按需下载方案

### 4.1 "仅荣耀可见"的判定
- 判定依据：`Build.MANUFACTURER` / `Build.BRAND` 等于 `HONOR`（2021 年荣耀独立后的新机型，荣耀 400 属此类），叠加 `Build.FINGERPRINT` 前缀 `HONOR/` 双重校验；应用启动时判定一次并缓存。
- 非荣耀设备行为：设置页不渲染"桌面小组件"入口；不触发组件下载/安装流程；P1 拆包后基础安装包内不含任何组件代码（天然不可见）。
- 边界：老荣耀机型（品牌字段为 HUAWEI、Magic UI 4 及以前）默认不兼容，避免误伤华为手机；确需覆盖可加机型白名单，按需再议。
- 局限：侧载分发没有商店级机型定向，只能在应用内判定；若日后上架"荣耀应用市场"，可叠加商店级机型分发。

### 4.2 "按需下载"的可行路径

| 方案 | 机制 | 适配当前分发（GitHub 侧载 APK） | 结论 |
| --- | --- | --- | --- |
| A. Android 动态功能模块（DFM，SplitInstall） | 官方按需分片：主包 + 功能分片，由应用商店后台下发 | ❌ DFM 仅对商店渠道安装的应用生效，侧载 APK 无法使用 SplitInstall | 不可行（除非上架荣耀应用市场） |
| B. 同签名组件插件 APK | 组件代码独立打成小 APK，应用内下载 → 系统安装器安装；同签名下经 ContentProvider 共享快照 | ✅ 与现有 GitHub Releases 分发完全兼容 | **推荐** |
| C. 主包内置 + 荣耀门禁（软解锁） | 代码内置但非荣耀不注册入口、不显示 | ⚠️ 不是真按需下载，仅作 P0 快速验证过渡 | 过渡用 |

> 结论：侧载分发前提下，**方案 B 是唯一真正的按需下载路径**；未来若上架荣耀应用市场，可换官方 DFM（无系统安装弹窗、可静默更新，体验更优）。

### 4.3 推荐方案 B：双 APK 插件架构

```
基础安装包 sakura-japanese-x.y.z.apk（不含组件代码）
 ├─ 设置页"桌面小组件"入口（仅荣耀设备渲染）
 ├─ 组件模块管理器（荣耀判定 / 下载 / 签名校验 / 拉起系统安装器 / 版本检查 / 卸载）
 └─ WidgetSnapshotProvider（ContentProvider，signature 级权限，向插件暴露快照）
            │ 用户点击"下载并启用组件"（约 2–4MB）
            ▼
组件插件包 sakura-widget-x.y.z.apk（同一 keystore 签名）
 ├─ SakuraWidgetProvider（AppWidget）
 ├─ RemoteViews 布局 / 组件元数据 / 背景 drawable
 └─ 经 signature ContentProvider 读取主应用快照 → 随机渲染（§3.4）
```

- **签名一致是安全基石**：插件与主应用用同一 `sakura.keystore` 签名；ContentProvider 权限 `protectionLevel="signature"`，仅同签名应用可读，杜绝第三方读取学习数据。
- **版本联动**：主应用启动时经 `PackageManager` 读插件版本，过旧则在设置页提示"更新组件"，走同一下载流程。
- **卸载管理**：设置页提供"卸载组件"（`ACTION_DELETE` 系统卸载页）；组件被卸载后主应用自动回退"未安装"状态。
- **失败降级**：下载失败 / 安装被取消 → 主应用学习功能不受影响，设置页显示原因并可重试。

### 4.4 下载与安装流程（用户视角）
1. 荣耀设备打开「设置 → 桌面小组件」，显示"安装桌面组件（2.4MB）"。
2. 点击 → 应用内下载（进度条）→ 拉起系统安装确认 → 安装完成。
3. 桌面长按 → 添加小组件 → 选"樱花日语 单词卡"，即显示当前待复习/新词，此后按 §3.6 刷新机制更新。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| MagicOS 后台管理限制 WorkManager，组件长期不刷新 | 单词过期、提醒失效 | 即时刷新为主 + 系统兜底刷新；设置页引导用户放行后台 |
| RemoteViews 只支持标准控件 | 无法用自定义 View 做复杂动效 | 布局全部使用 TextView/ImageView/Button + 静态 drawable |
| 快照与应用状态短暂不一致（应用内操作后组件未刷新） | 组件显示旧词 | 每次状态变更即写快照；点击跳转后强制刷新组件 |
| 组件数据含 30 条候选池，久未开应用显示陈旧 | 误导用户 | `generatedAt` 超过 24h 显示"打开应用同步"提示 |
| 荣耀桌面/其他桌面兼容差异 | 部分机型尺寸怪异 | 只用标准 AppWidget API；真机回归荣耀桌面 + 华为桌面 |
| 双 APK 版本不同步（主应用已更新、插件过旧） | 组件行为与主应用不一致 | 主应用启动时读插件版本号，过旧则在设置页提示更新 |
| 插件包被手动卸载 | 组件消失、入口状态错乱 | 打开设置页时检测 `PackageManager` 存在性，自动回退"未安装"状态 |
| 下载失败 / 安装被取消 | 用户误以为功能损坏 | 主应用功能不受影响；设置页显示原因并可重试（§4.3 降级） |

## 8. 验收标准（荣耀 400 真机）

1. APK 正常安装（侧载或签名包），学习、复习、同步全流程可用，打孔屏/深色模式无破版。
2. 桌面可添加 2×2（及 P1 后 2×3）"樱花日语"组件，可调整位置与尺寸。
3. 有到期复习词时，组件展示的单词来自待复习池（随机）；清空到期词后自动切换为未学新词。
4. 点按组件打开应用并直达复习页（或新学页）。
5. 应用内学习/复习后，再次查看组件内容为最新；离线（飞行模式）下组件仍显示最近快照。
6. 连续多次刷新/点按"换一换"，单词在候选池内随机变化，不重复展示已"背完/熟词"。
7. 组件长时间不更新时显示"打开应用同步"提示，不展示过期数据。
